Critical gaps to add (must-have)

Inventory ledger (immutable): every in/out/adjust action writes a row (who/when/why). All stock levels should be derived from this ledger, not stored as a single mutable number.

Warehouses/locations: support multi-site stock and role scoping (manager can manage only assigned locations).

Batches & expiry (non-serialized): batch/lot number, manufacture/expiry, supplier—needed for recalls & FIFO/LIFO.

Item lifecycle (serialized): states like in_stock, issued, under_repair, retired, lost. Add reason codes.

Stock transfer flow: move between warehouses as two ledger rows (OUT from A, IN to B) with a single transfer reference.

Adjustments with reason & approval: negative/positive adjustments require a reason; optionally manager approval.

Soft deletes + audit trail: deleted_at, updated_by, updated_at everywhere; keep history tables or triggers.

Role/permission matrix (RBAC): explicit policy for: create/read/update/delete for Items, Serials, Batches, Ledger, Users, Reports, Transfers.

Concurrency control: use transactions + optimistic locking (e.g., version column) when updating quantities.

Input & bulk ops: CSV import/export for items, serials, batches; bulk print QR labels.

Search & pagination: server-side filters + indexed columns (name, sku, serial, batch, status).

Reports you’ll actually need:

Current stock (by item, warehouse)

Stock ledger (date range, item/warehouse filters)

Low stock vs reorder level

Aging/expiry (non-serialized)

Utilization & status breakdown (serialized)

Adjustment & transfer audit

QR security: encode a signed token (e.g., JWT) not just an ID; verify signature when scanning to prevent tampering.

Printable labels: templates (A4/Letter), label size presets (e.g., 38×38 mm, 50×25 mm), logo, SKU/Serial/Batch, short URL.

Views: v_current_stock, v_low_stock, v_batch_balances, v_serial_status.

Indexes: (sku), (serial_no), (item_id, warehouse_id), (batch_code), (created_at), plus partial indexes on active items.

API/Backend behaviors

Transactions for: receive stock, issue stock, transfer stock, batch split/merge.

Idempotency keys on write endpoints to avoid double submissions.

Background jobs: low-stock alerts, soon-to-expire batches, QR token rotation, nightly materialized-view refresh (if you add them).

File storage for images/labels (S3/Cloudinary); Replit storage is ephemeral.

Auth & security

MFA + password reset (Firebase Auth works well even if code runs on Replit).

Row-level authorization in queries (scope by warehouse for managers; staff read-only).

Rate limiting (reverse proxy or middleware).

Audit logging: user logins, permission changes, report downloads.

Mobile/PWA & QR scanning

PWA installability + service worker so it behaves like an app on phones.

WebRTC camera scan with graceful fallbacks (file upload, manual entry).

Accessibility: large tap targets, high-contrast labels, on-device flashlight toggle while scanning.
